**结论：`vendor/prompt-kit` 这个固定本地副本不支持原生批量渲染，但可以通过逐项调用返回批量结果。**

依据明确：本地版本为虚构的 `2.0.0`，全部实现只有：

```javascript
export function renderOne(input) { return String(input); }
```

它只导出 `renderOne`。直接传入 `["甲", "乙"]`，得到的是一个字符串 `"甲,乙"`，不是两项结果。另外，这个样例实际只做字符串转换，没有模板插值能力。

建议在调用侧增加最薄的一层封装：按输入顺序，每项调用一次 `renderOne`，再收集结果。例如输入 `["甲", "", "甲"]`，建议返回：

```json
[
  { "index": 0, "ok": true, "value": "甲" },
  { "index": 1, "ok": true, "value": "" },
  { "index": 2, "ok": true, "value": "甲" }
]
```

其中 `index` 对应输入位置。方案保证数量与顺序一致，保留重复项、空字符串，空集合返回 `[]`。无需修改第三方副本，也没有引入并发机制的必要。

本地实验 **5 条断言全部通过**，验证了导出范围、直接传数组的行为、逐项内容、结果数量和空集合。失败项结构已在方案中预留，但当前字符串输入无法触发渲染异常，不能声称异常隔离已经验证。
