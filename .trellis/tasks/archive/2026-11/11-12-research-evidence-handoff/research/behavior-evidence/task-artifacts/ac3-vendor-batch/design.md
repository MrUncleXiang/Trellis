# 批量渲染实现建议

## 核心选择

在业务侧包一层适配函数，保留固定第三方副本。依据：[能力核验](research/vendor-batch.md)。该副本仅提供同步单项函数；要得到多个独立结果，最短路径是逐项调用，无需改造依赖。

## 建议契约

- 输入：数组；非数组明确拒绝，避免把字符串按字符拆成批次。
- 输出：与输入等长且保持顺序的字符串数组；空数组返回空数组。
- 每个元素原样传给 renderOne，不额外改变其字符串转换规则。
- 建议出错时整批抛出异常，不返回半成品；这是待业务确认的建议，不是已确认要求。如果需要部分成功，再设计包含输入下标、结果或错误的逐项记录。

示意代码（仅方案，未写入业务模块；renderOne 的导入方式待接入工程验证）：

```javascript
function renderBatch(inputs) {
  if (!Array.isArray(inputs)) {
    throw new TypeError("inputs must be an array");
  }
  return Array.from(inputs, input => renderOne(input));
}
```

使用 Array.from 可使稀疏数组的每个位置也经过单项处理；普通数组的逐项行为已由研究实验验证，稀疏数组行为留待接入测试。不要直接调用 renderOne(inputs)：它只会得到整体字符串，例如 "alpha,beta"。

## 开发与验证建议

1. 确定业务模块位置、批次规模和失败策略；检查实际工程如何加载该依赖。该副本包配置与导出语法的兼容性不能由本次数据模块实验代替验证。
2. 在调用方增加适配函数，保持已有单项调用和第三方文件不变。
3. 验证单项、多个输入、顺序、重复项、空数组、非数组、稀疏数组及单项转换抛错的情况；普通字符串批次须得到数组而非合并字符串。
4. 在真实加载方式下复核接入；如规模导致界面卡顿，再测量并考虑分段调度。目前无性能加速证据，不引入并发。
5. 回退时撤销业务侧适配及新增调用，继续沿用单项接口；无需回退第三方包。
