# B：调研依据保存与交接——技术设计

日期：2026-11-12。状态：轻量方案与规划审查已通过，用户已要求实施，产品改动与本轮验证已完成，任务保持进行中待审阅/提交。活动需求见 [prd.md](prd.md)，执行顺序见 [implement.md](implement.md)。B-D1 已由用户“接受轻量方案”的回复解决；本设计经独立方案审查和一致性复查后通过，发现与修订见[规划审查记录](research/planning-review-2026-11-12.md)。

## 1. 从用户结果确定最小机制

真正要保存的不是“浏览器访问过什么”，而是“这个决定凭什么成立”。例如：为避免重复开发而决定复用某依赖，需要留下对应版本、相关能力的位置、限制及其对方案的影响。只有网址，下次还得重新推理；只有“支持”，下次不知道是哪个版本、什么条件。

完整结果至少依赖五件事：发现有用依据时写下来；来源能定位；结论与决定建立关系；接手入口能找到它；下游真的读到需要的部分。缺一项都可能变成“有文件但交接失败”。文件存在不能证明内容正确，自动捕获的浏览线索也不能替代解释。

因此本版修补既有指导链路，不增加数据库、工具事件适配器、评分器或任务字段。现状证据见 [当前流程分析](research/current-workflow-analysis.md)，外部实现比较见 [开源方案调查](research/github-research-persistence.md)。

## 2. 路线比较、推荐与保证边界

| 路线 | 谁做什么 | 可验证的保证 | 不能保证 / 代价 | 结论 |
|---|---|---|---|---|
| 只改规划技能 | 模型在规划时自行保存 | 规则能进入生成的技能 | 恢复和下游入口仍薄弱；模型遗忘仍丢 | 过窄，不推荐作为完整 B |
| 完整指导链路 + 已有状态提醒 | 模型保存和读取；已有宿主事件在支持处投递提醒 | 模板生成、规则可达、既有提示链路可以测试；行为用独立场景演练 | 模型忽略规则仍可漏记；无事件能力宿主没有每轮自动提醒 | **本版已选**，符合不新增运行时代码基线 |
| 自动捕获线索 + 可选结构检查 | 程序接收已支持的工具事件并留痕，模型整理成任务依据 | 在明确覆盖的工具/宿主范围，可独立于工作模型捕获线索；检查路径可由程序执行 | 覆盖、归属、隐私、配额、错误恢复需新增实现；不证明结论正确 | 本版不采用；以后若要求抵抗模型不配合，需另行扩大范围并验证能力 |
| 完整记忆服务 + 语义评分门禁 | 服务长期记录、检索，模型判断质量后拦截 | 可自动积累活动和执行评分策略 | 长期存储成本、误拦截、模型误判；仍无事实正确性保证 | 超出本题，不采用 |

三个开源项目提供的启发不同：文件式规划可帮助把决定与理由留下；每轮或工具前提醒可减少遗忘；工具后事件可自动捕获活动。不能因为某项目能阻止结束，就推导它能验证证据充分。固定提交、实际检查位置和未运行限制见调查报告；不把它们当作已安装的依赖。

**直接回答“是强门禁还是模型自觉”：本版不是程序强门禁。** 提醒投递可由现有程序触发，保存与解释仍由模型完成，审阅仍需人或检查代理判断。不会修改 `task.py start` 的拒绝条件。现有 A 管的规划材料检查与本版 B 的依据审阅不是一回事，不借 A 的检查宣传 B 已有强保证。

类比：本版是把交接清单放在工作台、在已有提示处提醒填写；自动捕获是机器记录操作轨迹。轨迹能证明“做过”，还需要说明“为何据此作决定”。

## 3. 文档语义契约

### 3.1 何时记录

只在外部依据用于支持、否定或改变当前需求、技术选择、兼容、风险或验收判断时触发。来源包括网页、未联网的第三方依赖源码、用户资料和验证外部行为的实验。日常阅读本项目代码、无关浏览不逐次建立报告。

当发现已足以用于决定，应在对用户给出该结论、据此修改方案或转入另一主题前先保存；同一主题随调查增量更新，不等到会话收尾。复杂调查尚未有结论时，可先记已查范围和关键未知。这里没有按工具次数计数，也不能抵抗模型忽略或进程突然中断。

研究代理先把结果写入当前任务的 `research/`，再返回路径和摘要；主代理验收后才把它当依据。无法保存时应报告失败，不声称已完成交接。

### 3.2 一份有用记录必须回答什么

以下是语义内容，不要求固定标题、顺序、篇幅或字段，也不要求每次查询新建文件。

| 内容 | 足够回答的问题 |
|---|---|
| 调查问题 | 为当前哪个问题而查？ |
| 可定位来源 | 去哪里能找到相关原文、源码位置或复查实验？版本何时影响结论？ |
| 事实与限制 | 实际看到什么？哪些前提、版本或范围下成立？ |
| 决策影响 | 为什么因此采用、放弃或调整方案？ |
| 推断与未知 | 哪些是解释或假设？哪些未查明？会不会改变约定结果？ |
| 备选说明（仅实际比较时） | 排除了什么，具体理由是什么？未比较时不虚构比较过程 |

事实、推断和未知可在普通段落中区分，无需统一标签或分数。不能用附链接代替推理，也不能把模型总结伪称原文。

来源最低定位方式：网页提供链接及章节、符号或相关位置；版本敏感时记录版本/提交/查阅时间。本地第三方依赖提供包名或路径、实际版本及符号/文件位置。用户资料说明提供来源，不声称独立验证。实验保存环境、步骤或命令及观察结果；不保存无关全量日志。

### 3.3 文件和路径

- 新记录优先 `research/<topic>.md`，按问题主题命名；既有可定位文件继续复用，不强制搬迁。
- 任务正文里的记录定位按任务目录理解；实际 Markdown（轻量文档格式）链接按链接所在文档目录解析。例如 `prd.md` 中为 `research/compatibility.md`，同目录 `research/` 内的记录互链可用 `other-topic.md`。
- `implement.jsonl` 与 `check.jsonl` 中 `file` 按仓库根解析，例：`.trellis/tasks/<task-dir>/research/compatibility.md`。不改变逐行 JSON（结构化数据格式）的现有格式。
- 复用其他任务记录可以直接引用，但确认其仍可访问、关键前提适用；若对方将归档或删除，应更新引用，必要时只保留当前决定所需的摘要与来源，不盲目复制整库。
- 不依赖自动递归追踪文档链接：主代理应选取所需记录到角色清单或派发要求，下游按明确引用读取。

### 3.4 接手入口与状态

`prd.md` 的 `## Research` 用简短文字呈现三种情况，允许在同任务中并存，不新增机器枚举或任务状态：

1. 无需调查：给出与当前任务有关的原因，不创建空文件。
2. 复用已有调查：结论、引用及关键前提适用性；版本敏感时核对版本。
3. 已调查：关键结论、记录引用；未解决问题及其影响/处理决定。

“尚未调查”“已查无可靠答案”“无需调查”必须分开表达。需要调查却没有做，不能用“无需”填空。`design.md` 中具体决定附近引用同一记录；不把整篇调查复制到多份规划材料。

### 3.5 最小例子

下面是示意，不是任何真实库的能力声明，也不是强制模板。

`prd.md` 的 `## Research` 可以只有：

> 已查本地依赖 X 的版本 2.0；接口只能处理单项，批量需求需在调用方组合。依据位置为 `research/compatibility.md`（示意路径）。并发上限尚未知；当前首版按顺序执行，该未知不改变约定行为。

`research/compatibility.md` 可以写：

> 问题：现有依赖能否直接支持本任务批量处理？事实：本地依赖 X 2.0，文件路径和符号位置显示公开接口只收一个输入。推断：当前不能直接传数组，应逐项调用。决定：首版顺序组合，保留失败项信息。限制：未验证并发上限，不能据此承诺吞吐量。实际排除：因不兼容当前输入，放弃直接批量传参。

真实记录必须把“文件路径和符号位置”替换为实际可定位证据；这里的示意不能用于通过验收。简单文案任务则只需写“无需外部调查，现有界面措辞和本地规范足以判断”，没有 `research/` 也可符合 B。

## 4. 端到端流程与责任

| 时点 | 责任人/代理 | 必须动作 | 下游收到什么 |
|---|---|---|---|
| 1.1 识别问题 | 主代理 | 区分仓库可回答、外部待查、用户决定；若外部决定有依据则按语义记录 | 待查问题或可用记录 |
| 1.2 调研 | 主代理或研究代理 | 有用发现及时保存；写清来源、限制、决定影响；无答案也说明范围。研究派发以 `Active task: <task path>` 开头，提供具体问题、目标文件和最低语义内容；任务不明时返回主代理确认，不猜测 | 当前任务研究文件/可用复用引用 |
| 1.2 研究代理返回 | 主代理 | 实际读取文件，检查问题、来源、结论/限制、决定影响及事实/推断/未知；核对关键出处；建立 `prd.md` 入口。文件缺失或语义不足则退回补齐，不能仅接受返回摘要 | 集成后的关键结论，非聊天孤立路径 |
| 1.3 选上下文 | 主代理 | 实施需要的能力/限制放实施清单；验收需要的依据放检查清单；无关报告不全量注入 | 角色需要的规范与研究路径 |
| 1.4/1.5 审阅 | 主代理和用户 | 状态、记录、引用、限制、未知处理均清楚；重大未知回到 1.1；保留既有开工授权要求 | 可审阅规划摘要，非新脚本放行票 |
| 恢复任务 | 新会话主代理 | 经 `trellis-start` 或 `trellis-continue` 进入已有任务时，从任务材料读取 `## Research` 和所需引用；进入规划审阅或继续实施前复查未知与关键前提。恢复中发现用于决定的新外部依据时，按第 3.1—3.2 节保存规则先记录后给结论，含来源冲突或未查明的情况。尚无需求文件则按原流程创建，不要求读取不存在内容 | 不依赖原聊天的当前决定 |
| 2.1 实施前 | 实施主代理/子代理 | 实际读取相关记录；确认适用版本；缺失或关键未知影响实现时回规划 | 对既定结果和限制的一致理解 |
| 2.2 检查 | 检查主代理/子代理 | 逐个关键决定对照引用，抽查相关原文位置；确认结果符合已约定限制；来源存疑不默认为通过 | 具体问题或可复核验收证据 |
| 2.3 发现变化 | 主代理协调 | 补查、更新记录和受影响决定；若改变范围/行为/兼容/风险，回规划重审 | 当前结论清楚，旧结论标为已替代 |

研究代理只写当前 `research/`，不扩权修改需求。主代理负责把结论纳入 `prd.md` / `design.md`、维护清单并判断是否需要用户决定。实施/检查子代理遇到会改变决定的新证据，应向主代理报告来源、发现与影响；不得仅因通用状态提醒自行改写需求、设计或任务研究入口，主代理在采用发现前负责保存、集成或安排补查。该要求不撤销其原本明确获准的代码/测试等写入范围。实施和检查子代理不一定调用共享技能，不能只修改 `before-dev.md` / `check.md` 就声称覆盖所有代理；要在 2.1/2.2 派发要求和角色清单明确相关资料。

本版无需改加载器。已有事件注入能将清单文件送入部分代理；拉取式代理的读取仍依赖其执行入口要求。大文件仅选择当前决定所需章节并保留原出处，不以全量塞上下文证明已理解。

## 6. 提醒机制与平台能力边界

复用 `inject-workflow-state.py` 及现有同类状态注入读取 `workflow.md` 正文的路径；不增加计数器、定时器或新事件。规划提示候选语义是“主会话在外部依据影响决定时及时保存，并在任务研究入口引用；无需调查说明原因”。执行提示候选语义是“主会话在补查改变决定时，先保存并更新入口，涉及结果变化则回规划；实施/检查子代理向主会话报告来源、发现和影响，不因本提醒自行改写任务规划。研究子代理只按分配范围保存研究文件并返回路径”。最终产品文字遵循现有模板语言和平台中立要求。

- 提醒按已有用户输入事件出现，不是每次工具调用后触发；同一长轮内不会因此多次提醒。
- 有状态注入能力的宿主需要运行现有钩子，且项目使用新工作流；脚本无须改变。
- 没有该事件或未启用注入的宿主，通过技能、恢复命令和流程文档获得同一规则，不声称自动每轮提醒。
- 子代理不能因读到主会话提示再次派发自己；新增提醒需分别限定主会话集成、研究代理保存和实施/检查代理报告的职责，不能通过通用提示扩大既有写入权限。
- 22 个平台注册输出是生成层覆盖，不是 22 个宿主的事件能力承诺。实施时按真实运行环境报告“生成验证”和“宿主行为验证”。

## 7. 异常、变化和数据边界

| 情况 | 处理 | 不得声称 |
|---|---|---|
| 查无结果或来源冲突 | 保存已查范围、冲突、当前理由与影响；涉及用户决定则继续规划 | “未找到”等于“不存在”，或无依据宣称就绪 |
| 新证据推翻结论 | 同主题更新并标注旧结论已替代，更新需求/设计引用及角色清单 | 两个相反结论都仍有效 |
| 来源失效/本地依赖升级 | 复核当前可定位材料和适用版本，关键前提不明则回规划 | 单凭旧链接或旧版本可继续依赖 |
| 引用丢失/路径错误 | 使用当前任务入口修正；找不到则说明缺口，重新核查关键依据 | 静默跳过并认为已读完 |
| 文件写入失败或会话中断 | 报告未持久化；恢复时核对入口和文件；本版不能自动补回未保存结果 | 没有错误提示即已安全保存 |
| 多个研究代理并行 | 按主题分配不相交文件；主代理串行集成入口；不让多个代理同时改 PRD（需求文档） | 用最后一次覆盖解决事实冲突 |
| 大量调查/上下文过大 | 合并同主题结果、入口只留决定与引用；按角色加载，不全量注入 | 文件越多越可靠 |
| 资料含密钥/个人数据/受限内容 | 仅保存必要事实、可访问的出处标识；剔除凭据和无关个人数据，遵循项目访问边界 | 为追溯而保存全部原始请求响应 |
| 无法联网但本地资料足够 | 用本地包标识、版本、符号位置照常记录 | 没网址就不是外部依据 |

不新增完整历史账本；一次结论变更只需足够区分现行与已替代。历史任务不回填，既有文件无需强制迁移；本任务需求快照因重排活动文档而保留原文，属于本次追溯证据，不推广为每次规划必备文件。

## 8. 兼容、更新、依赖与回滚

- B 独立于 A 的规划材料门禁、C 的归档来源；不增加 A/C 的字段或启动/归档条件。共同编辑的规划技能和工作流在实施前按父任务协调，不覆盖另一个任务的差异。
- 保持状态标签、平台条件语法、逐行清单格式、角色边界和加载器不变。只更新文案及验证，不引入自动目录扫描或递归链接解析。
- `marketplace` 是独立子模块。其三个变体需要单独审阅、测试和提交；主仓库引用按项目发布规范协调。不能仅改主引用而未保留子模块内容，也不能用主仓库提交代替子模块提交。
- 发布按现有构建、更新与哈希跟踪路径；是否需要版本迁移清单，按实施时的升级规范和实际路径/结构变化决定，不为纯内容变更先发明迁移器。
- 当前工作树已有其他任务改动。只更新本任务相关生成目标，审阅更新预览和冲突；禁止用全局强制覆盖图省事。
- 回滚只撤销本任务模板/测试/生成目标的差异及对应子模块引用，保留其他任务修改。若已发布，走正常版本更新恢复内容，不回退用户任务记录。

## 9. 验证策略与可信度

三层证据必须分开：

1. 静态一致性：需求、入口、路径、角色语义及工作流变体无冲突。
2. 自动契约检查：从最新源构建后，真实配置器输出包含规则；状态提示块仍解析且由现有链路输出；更新不破坏共享目录与已有文件。这证明入口可达。
3. 行为演练：主会话实际保存，再给无原聊天的新会话仅任务路径，观察其能否重建依据、读取限制并处理未知；有实际子代理路径时同样验证。这提供特定模型/宿主/情境的行为证据，不是必然遵循的数学保证。

测试不以“有关键词”作为需求通过标准，也不用任意分数掩盖语义审阅。结构自动化不新增为生产门禁。十个场景、输入与失败条件见 [场景验证计划](research/scenario-validation-plan.md)，具体命令与顺序见 [implement.md](implement.md)。当前未执行产品修改、模型行为演练或自动捕获验证。

## 11. 自动捕获备选路线（未纳入本版）

本节只回答“若需要抵抗模型忘记保存，技术上要增加什么”。不新增承诺，不预设跨平台实现，也不是开始编写脚本的授权。

### 11.1 目标与不能混淆的结果

如果未来明确要求扩大范围，应先定义：在明确列出的宿主与工具上，即使工作模型不写文件，程序仍能保存必要的来源活动线索。线索不是已采纳的任务结论，不应直接覆盖 `prd.md` / `research/` 权威材料。模型或主代理仍需核对并提升为决定依据。

### 11.2 候选链路与事件契约

宿主提供工具完成事件 → 适配层归一化并过滤 → 绑定当时任务/会话 → 写本地追加队列 → 主代理按需读取候选 → 核对来源与决定影响 → 写现有任务记录与入口。

候选事件最少需要：协议版本、事件唯一标识、时间、宿主/会话/父子关系、工具类型、调用标识、当时任务标识或无归属、可定位来源与操作摘要、截断/错误标记。字段名和存储格式在能力试验后确定，不在本版扩展 `task.json`。

任务归属必须在事件产生时固定，不能后台稍后读取“当前任务”导致切换任务后串写。归属不明时进入未归属候选，不能猜测。按事件/调用标识去重；重复、乱序、子代理返回和延迟到达需可识别。原始工具负载不默认全存；先过滤密钥/敏感数据并限制体积与保留期。写入失败必须有可观察诊断，不允许宣传“静默绝不丢失”。

### 11.3 开始扩展前必须验证的能力

| 能力 | 最小实验 |
|---|---|
| 工具后事件是否存在且真实执行 | 在目标宿主用一个实际网络工具和一个本地第三方源码读取工具触发并检查事件 |
| 数据够不够定位 | 核对返回的是来源、结果摘要还是仅成功状态；不足时明确降级范围 |
| 浏览器内操作、命令行网络、子代理 | 分别实测；不因“有工具事件”假定都覆盖 |
| 任务切换、无活动任务、异步与会话恢复 | 固定归属并试验延迟/重复/中断，确认不串任务 |
| 敏感数据、容量、写入故障 | 合成无真实密钥的测试，验证过滤、配额、失败提示和恢复 |
| 用户控制 | 明确启停、数据位置、清理与保留，不自动安装后台常驻服务 |

当前仅检查了 Trellis 已注册的事件，未做这些宿主能力实测。缺事件的宿主只能显式降级为本版指导链路；若用户要求所有平台同等强度，则需要另行确认是否可接受不支持的平台，而非假装通用。

### 11.4 结构门禁的另一个选择

程序可以检验已声明状态、文件存在、链接可定位；但它不能知道模型是否漏报“其实调查过”。若加入此类启动拦截，必须另定无需调查与复用的结构表达、错误消息、兼容迁移、人工例外和测试，且仍不能称语义质量强保证。本版不做。自动捕获与结构拦截是两项独立选择，不能打包当成必然需要。
