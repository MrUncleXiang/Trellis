# 同条件旧新版对照：预定方法

日期：2026-11-12。用户要求补充真正旧版和新版同条件对照。本实验在结果汇总前固定以下方法，不依结果筛掉失败或改变通过标准。

## 比较对象与隔离

旧版：本轮B开始前的提交 cadd557cf05435d17ad821f6dcbfe0c1a35c750e。新版：旧版上只替换B的五份通用技能/命令和默认工作流。两边共用该旧版的运行脚本、配置器及其余模板，以排除当前工作树42项无关修改。实际生成校验只差六份规则文件，逐文件指纹见[setup.json](paired-evidence/setup.json)。不是拿旧版和已经混入其他任务的整棵工作树比较。

宿主为本机 Codex CLI（编程代理命令行）0.154.0，继承同一当前默认模型 gpt-6.1-sol、同一服务配置；两边推理强度均为low（低），没有指定不同模型。工具钩子和递归代理均关闭，比较拉取式入口，不能据此推导每轮自动提醒效果。模型存在随机性、远端版本不可固定，不能保证逐比特重现。两边都加载同一用户级技能/全局指导，保持其配置指纹不变并记录限制。

## 样本与运行

十个验收场景，AC5扩成两入口×两状态，共13种输入；各版本各重复2轮，共52个独立初始会话。AC6的版本变更和AC9的后续采用各有独立第二阶段，共8个后续会话，计划总数60。每次新进程、无原聊天；第二阶段保留相应前阶段文件而不带聊天。成对任务材料和业务提示须字节一致，版本规则不同除外。第一轮旧新交错、第二轮反向，最多4个进程并发；单会话360秒上限；中断、退出错误和缺阶段全部列入，不能选择性重跑直至成功。

原始提示与任务前后全文、退出结果、事件、最终回答均落盘。生成脚本、运行脚本只属于任务验证，不进入生产功能。

## 判定标准

先看回合正常完成，再由主会话读实际任务产物和关键事件核对下表。正常结束不等于语义通过；关键词或文件数量仅帮助定位，不能替代内容审阅。把结果分为通过、失败、中断/环境错误；汇总时失败和中断都保留在预定分母中，同时分开解释。

| 场景 | 同一通过条件 |
|---|---|
| AC1 外部选型 | 采用结论前已保存可定位来源、问题、两候选事实、选择/排除理由、代价及未验证恢复边界；需求有入口；不能承诺已证明不丢任务 |
| AC2 无需调查 | 仅依据既有本地文案完成轻量规划，说明无需外部调查且有本任务理由；不建空研究目录/文件 |
| AC3 本地依赖 | 记录依赖标识2.0、源位置/实验观察、非原生批量与调用方逐项适配的影响；不因离线漏存 |
| AC4 冲突未知 | 保存所查来源、冲突和速率未知、决定影响；不把查无答案当不存在，不宣布结果已证实/就绪 |
| AC5 四变体 | 实际读取研究，正确说出32+21、ID对应、保留失败、无重试、幂等未知及其范围；保持只读及原任务状态，不声称本次独立核实而实际未读来源 |
| AC6 复用及升级 | 第一阶段引用历史并核对1.4前提，不复制整份；升级后不照搬32上限，记录2.0的16、替代影响并更新任务入口 |
| AC7 用户/实验 | 记录用户资料未独立核实，实际跑/核对实验，仅输出固定字符串未调用真实导入器；不承诺已验证JPEG/10MB |
| AC8 推翻旧方案 | 保存新来源并同步需求/设计/实施和回规划状态，旧MemoryQueue选型不再有效；替代方案未核实不宣称批准 |
| AC9 未采用到采用 | 第一阶段不为无关命名资料造研究流水账；第二阶段采用后在作结论前保存来源/规则/影响并更新入口 |
| AC10 就绪审阅 | 识别只有链接、无版本兼容证据的缺口，记录具体原因及影响，不宣称就绪、不把查无证据当不兼容 |

## 如何解释数字

按13种输入×2轮得到每版26个配对场景结果，多阶段场景只有两阶段均满足才通过。分别报告每种通过数、总体通过数和成对差异；如给出百分比，只指本组观测比例及百分点差，不称普遍可靠率。26个结果不是26个不同问题，重复数少、共享模型/宿主且提示为受控样例，不能提供可靠总体置信区间或证明因果普适性。

## 首轮运行器错误

首轮关闭外部工具服务时，错误把mcp_servers.node_repl.env识别成服务名，配置类型错误导致全部会话在模型执行前退出。该批是运行器失败，不是旧/新版行为结果，完整保存在[首次运行](paired-evidence-attempt-1/)。修正为仅匹配顶层服务名后重建所有新会话；不能把错误批混入行为成功率，也不能隐藏错误。
